# ぜんぶナビ

ジャンルを問わず、主要メディアのニュースを一か所で確認できる総合ポータルです。
国内・国際・経済・IT・エンタメ・スポーツ・ゲーム・新商品/グルメ・ライフまで、各媒体の RSS から見出しを自動で収集し、**同じ出来事を報じた記事を「トピック」に自動でまとめて**、話題の大きさ順に表示します。

> サイト名は `src/config/site.ts` で変更できます。

## 主な機能

| 画面 | 内容 |
| --- | --- |
| トップ `/` | 複数媒体が報じた「いま話題のニュース」、ジャンル別の見出し、よく読まれている記事・SNSで話題の記事・新着 |
| ジャンル `/genre/[slug]` | ジャンル別のトピック一覧（話題順／新着順、ページ送り） |
| トピック `/topic/[id]` | 1つの出来事について各媒体の報道を時系列で読み比べ |
| 検索 `/search?q=` | 見出しの部分一致検索（日本語対応の trigram インデックス） |
| ランキング `/ranking` | 話題のトピック・よく読まれている記事・SNSで話題の記事 |
| 掲載メディア `/sources` | 収集元と収集状況の公開 |
| 運営方針 `/about` | 掲載方針・掲載停止依頼の窓口・免責 |

- 元記事へのリンクは `/go/[id]` を経由してクリック数を集計します（ボットと先読みは除外）。
- 見出し・最大120文字の要約・リンクのみを保持し、**本文や画像は転載しません**。
- `sitemap.xml` / `robots.txt` / OGP / canonical を出力します。単独記事のトピックは `noindex` です。

## 技術構成

- Next.js 16（App Router, ISR）/ React 19 / TypeScript / Tailwind CSS 4
- PostgreSQL 16 + Prisma 7（`@prisma/adapter-pg`）
- RSS 2.0 / RSS 1.0 (RDF) / Atom を `fast-xml-parser` で解析
- テスト: Vitest

```
prisma/
  schema.prisma      Genre / Source / Article / Topic
  catalog.ts         ジャンルと収集フィードのマスタ（ここを編集して db:seed）
scripts/
  crawl.ts           収集 CLI
  recluster.ts       トピックの全再構成
src/lib/
  feed/              取得した XML の解析・テキスト整形
  crawl/             フィード取得（条件付き GET・タイムアウト・サイズ上限）と収集処理
  topics/            トピック自動まとめ（類似度・割り当て・話題度スコア）
  queries.ts         画面用のデータ取得
src/app/             画面・API（/api/cron/crawl, /go/[id]）
```

## セットアップ

前提: Node.js 22 以上、PostgreSQL 16（`pg_trgm` 拡張が使えること）

```bash
cp .env.example .env          # DATABASE_URL などを設定
npm install                   # prisma generate も実行される
npm run db:migrate            # テーブルと検索インデックスを作成
npm run db:seed               # ジャンルと収集フィードを登録
npm run crawl                 # ニュースを収集してトピックを作成
npm run dev                   # http://localhost:3000
```

| コマンド | 内容 |
| --- | --- |
| `npm run crawl` | 収集（前回取得から10分未満のフィードはスキップ）。`-- --force` で全件 |
| `npm run recluster` | まとめ方のパラメータ変更後にトピックを全再構成（トピック ID が変わる） |
| `npm test` / `npm run lint` / `npm run typecheck` | テスト・静的検査 |
| `npm run build` | 本番ビルド（ビルド時に DB へ接続します） |

## 定期収集

収集は `GET /api/cron/crawl` を `Authorization: Bearer $CRON_SECRET` 付きで呼び出して実行します。`CRON_SECRET` が未設定の場合は常に 401 を返します。
10〜15分間隔での実行を想定しています（例: Vercel Cron、GitHub Actions の schedule、サーバーの cron から `curl`）。サーバー上で直接 `npm run crawl` を cron 実行しても構いません。

収集処理の方針:
- 同一ホストのフィードは直列・1秒間隔、ホスト間は最大6並列
- `ETag` / `Last-Modified` による条件付き GET、15秒タイムアウト、5MB 上限
- 7日より古い記事は取り込まず、90日を過ぎた記事は削除
- クローラーは `ZenbuNaviBot/1.0 (+<サイトURL>/about)` を名乗ります

## トピック自動まとめ

見出しを文字 bigram に分解し、TF-IDF ベクトルのコサイン類似度で同じ出来事の記事を束ねます（`src/lib/topics/`）。
新着記事は直近48時間のトピックに追加し、既存の割り当ては変更しないため、トピックの URL は安定します。

既定値は実データ（48時間分・約1,600記事）で誤結合と取りこぼしを確認して決めています。

| パラメータ | 値 | 理由 |
| --- | --- | --- |
| 類似度の閾値 | 0.30 | |
| IDF の指数 | 2 | 固有名詞など希少な語を重視 |
| 最小出現文書数 | 2 | 1記事にしか出ない bigram は一致し得ず類似度を下げるだけなので除外 |
| 共通特徴量の最小数 | 3 | 「福島vs水戸」「福島vs長野」のような1語一致を防止 |
| 同一媒体どうしの閾値 | 0.60 | 連載・定型見出し（「〇〇vs〇〇 試合記録」など）の誤結合を防止 |

話題度スコアは「報じた媒体数」を主軸に、はてなブックマーク数・サイト内のクリック数を加味し、経過時間で減衰させます（`src/lib/topics/score.ts`）。

## 収集フィードと規約確認

`prisma/catalog.ts` に 70 フィードを登録しています（有効 49）。
**媒体側のボット対策で自動取得が拒否された 21 フィード（朝日新聞・毎日新聞・日刊スポーツ・TBS・日テレ・ナタリーなど）は、回避せず停止しています。**提携・許諾を得た後に `active` を有効にしてください。
なお NHK の RSS は 2026年8月8日以降更新されていないため登録していません。

商用公開の前に、各媒体の RSS 利用規約（商用利用・見出しの転載・リンク方法の条件）を必ず確認してください。掲載停止の依頼には `/about` の窓口で対応する運用を想定しています。
